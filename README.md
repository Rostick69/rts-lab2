![Python](https://img.shields.io/badge/Python-3.10%2B-3776AB?logo=python&logoColor=white)

Практическая работа №2 по дисциплине «Системы реального времени».

Консольное приложение на Python, которое по описанию фрагмента кода (последовательности операций) и модели процессора оценивает наилучшее (BCET) и наихудшее (WCET) время выполнения в тактах с учётом промахов кэша и ошибок предсказания переходов.

**Вариант 2: шаг ПИД-регулятора** (чтение уставки, вычисление, вывод на привод).

## Функциональные возможности

- **Модель операции и модель процессора** оформлены через `@dataclass`
- **Лучшее время операции** — все обращения к памяти попадают в кэш, все переходы предсказаны верно
- **Худшее время операции** — каждое обращение к памяти даёт промах кэша, каждый переход — ошибку предсказания
- **BCET и WCET** фрагмента — суммы лучших и худших времён операций
- **Коэффициент недетерминизма** `K = WCET / BCET`
- **Вклад источников** (базовое выполнение, память, ветвления) в наихудшее время — в тактах и процентах
- **Проверка дедлайна**: укладывается ли фрагмент в худшем случае, и какой остаётся запас
- **Исходные данные** читаются из JSON-файла, в коде нет «магических чисел»
- **Проверка данных** при загрузке: неизвестный тип операции, отрицательные значения, пустой фрагмент или нулевой дедлайн дают понятную ошибку

## Краткие теоретические сведения

**WCET** (Worst-Case Execution Time) — наихудшее время выполнения фрагмента кода, верхняя граница, которую фрагмент не превысит ни при каких допустимых входных данных и состояниях процессора. **BCET** (Best-Case Execution Time) — наилучшее время.

Для систем жёсткого реального времени важно именно наихудшее время: дедлайн должен выполняться всегда, а не в среднем.

### Источники недетерминизма

| Источник | Лучший случай | Худший случай |
|----------|---------------|---------------|
| Кэш | Данные уже в кэше (попадание) | Промах — данные читаются из медленной памяти |
| Предсказание переходов | Переход предсказан верно, конвейер не останавливается | Ошибка предсказания — конвейер очищается и заполняется заново |

### Расчётные формулы

| Величина | Формула |
|----------|---------|
| Лучшее время операции | `base` |
| Худшее время операции | `base + m·P_miss + b·P_br` |
| BCET | `Σ лучших времён = n·base` |
| WCET | `Σ худших времён = n·base + M·P_miss + B·P_br` |
| Коэффициент недетерминизма | `K = WCET / BCET` |

где `m`, `b` — обращения к памяти и ветвления в операции; `M`, `B` — их суммы по фрагменту; `P_miss`, `P_br` — штрафы промаха кэша и ошибки предсказания.

## Входные данные

Данные варианта лежат в `data/variant2.json`. Все времена в тактах.

```json
{
    "title": "шаг ПИД-регулятора",
    "processor": {
        "base_cost": 1,
        "cache_miss_penalty": 20,
        "mispredict_penalty": 10
    },
    "deadline": 300,
    "operations": [
        {"name": "Чтение уставки r", "type": "чтение", "mem_accesses": 1, "branches": 0},
        ...
    ]
}
```

| Поле | Описание |
|------|----------|
| `title` | Название фрагмента (выводится в заголовке) |
| `processor.base_cost` | Базовая стоимость одной операции, такты |
| `processor.cache_miss_penalty` | Штраф промаха кэша на одно обращение к памяти, такты |
| `processor.mispredict_penalty` | Штраф ошибки предсказания на одно ветвление, такты |
| `deadline` | Дедлайн фрагмента, такты |
| `name` | Название операции |
| `type` | Тип: `чтение` / `запись` / `вычисление` / `ветвление` |
| `mem_accesses` | Число обращений к памяти |
| `branches` | Число ветвлений (условных переходов) |

## Пример работы

Результат для варианта 2:

```
Оценка WCET: шаг ПИД-регулятора

Операция                     | Тип        | Память | Ветвл. | Лучшее | Худшее
-----------------------------------------------------------------------------
Чтение уставки r             | чтение     |      1 |      0 |      1 |     21
Чтение измерения y с АЦП     | чтение     |      1 |      0 |      1 |     21
Ошибка e = r - y             | вычисление |      0 |      0 |      1 |      1
P = Kp * e                   | вычисление |      1 |      0 |      1 |     21
I = I + Ki * e * dt          | вычисление |      2 |      0 |      1 |     41
Ограничение интеграла        | ветвление  |      0 |      2 |      1 |     21
Чтение прошлой ошибки e_prev | чтение     |      1 |      0 |      1 |     21
D = Kd * (e - e_prev) / dt   | вычисление |      1 |      0 |      1 |     21
Сумма u = P + I + D          | вычисление |      0 |      0 |      1 |      1
Ограничение выхода u         | ветвление  |      0 |      2 |      1 |     21
Сохранение e_prev и I        | запись     |      2 |      0 |      1 |     41
Вывод u на привод (ШИМ)      | запись     |      1 |      0 |      1 |     21
-----------------------------------------------------------------------------
Итого                        |            |     10 |      4 |     12 |    252

ЗАКЛЮЧЕНИЕ
Модель процессора: базовая стоимость 1 такт, промах кэша +20, ошибка предсказания +10
Операций: 12, обращений к памяти: 10, ветвлений: 4
BCET = 12 тактов (все попадания в кэш и верные предсказания)
WCET = 12 + 10·20 + 4·10 = 252 такта
Коэффициент недетерминизма: K = WCET / BCET = 252 / 12 = 21
Вклад источников в WCET:
  базовое выполнение                12 тактов (4.8 %)
  память (промахи кэша)            200 тактов (79.4 %)
  ветвления (ошибки предсказания)   40 тактов (15.9 %)
Дедлайн: 300 тактов
Вывод: в худшем случае фрагмент укладывается в дедлайн (запас 48 тактов).
```

### Функции расчёта (`calculations.py`)

| Функция | Что делает |
|---------|------------|
| `best_case(op, model)` | Лучшее время операции: `base` |
| `worst_case(op, model)` | Худшее время операции: `base + m·P_miss + b·P_br` |
| `bcet(fragment, model)` | BCET — сумма лучших времён |
| `wcet(fragment, model)` | WCET — сумма худших времён |
| `nondeterminism_ratio(fragment, model)` | `K = WCET / BCET` |
| `source_breakdown(fragment, model)` | Вклад базы, памяти и ветвлений в WCET |
| `fits_deadline(fragment, model, deadline)` | `WCET ≤ дедлайн` |
| `total_mem_accesses(fragment)`, `total_branches(fragment)` | Суммарные обращения к памяти и ветвления |

## Сборка и запуск

### Требования

- Python 3.10 или выше
- Сторонние библиотеки не нужны, используется только стандартная библиотека

### Через Visual Studio

1. Клонировать репозиторий: **Git → Clone Repository...**
2. Открыть `rts-lab2.slnx`
3. В Solution Explorer: правой кнопкой по `src/main.py` → **Set as Startup File**
4. Запустить (**Ctrl+F5**)

Чтобы запустить программу с другим файлом данных, укажите путь в **Properties → Debug → Script Arguments**, например `data/example_methodichka.json`.

### Через командную строку

```bash
git clone https://github.com/Rostick69/rts-lab2.git
cd rts-lab2

python src/main.py                                  # вариант 2
python src/main.py data/example_methodichka.json    # контрольный пример из задания
```
